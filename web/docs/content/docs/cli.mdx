## skiff deploy

Build and deploy the current app to your server

Deploy builds your app, runs it, and serves it at a URL. Reads config from skiff.toml.

```sh
skiff deploy [flags]
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--build-timeout` | `15m0s` | cancel the build if it runs longer than this |
| `-c`, `--config` | `skiff.toml` | path to skiff.toml |
| `--context` |  | directory to build from (default: the directory holding skiff.toml) |
| `--name` |  | override the app name (e.g. for preview environments) |
| `--timeout` | `0s` | how long to wait for the new version to become healthy (default: health_timeout in skiff.toml, else 30s) |

## skiff job

Manage an app's scheduled jobs

### skiff job add

Add a job that runs on a schedule, when its webhook is called, or for each new file in a bucket

```sh
skiff job add <app> <name> [flags]
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--bucket` |  | start the job for each new file in this bucket of your team's |
| `--catch-up` |  | "skip" drops runs missed while the server was down (default: run once) |
| `-c`, `--command` |  | what the job runs |
| `--prefix` |  | only files under this folder of the bucket, like incoming/ |
| `--retries` | `0` | how many more times a failed run is tried, up to 10 |
| `-s`, `--schedule` |  | cron schedule in the server's time zone, like "0 3 * * *" |
| `--timeout` | `0s` | how long a run may take, like 2h (default 30m) |
| `--webhook` |  | give the job an address that starts it when a signed request arrives |


## skiff mcp

Serve your Skiff projects to AI agents over MCP (stdio)

Runs a Model Context Protocol server on stdin/stdout so an agent can list projects, deploy, read logs and traffic, edit env vars, roll back, and manage workers, jobs, databases, buckets and volumes.  Uses the dashboard you signed in to with skiff login, or SKIFF_URL (e.g. https://dash.example.com) and SKIFF_TOKEN (Settings → API tokens).  With --read-only, or SKIFF_MCP_READONLY=1, the tools that change things (deploy, rollback, set_env, and the ones that create or change workers, jobs, databases, buckets and volumes) are left out. No tool deletes a database, bucket or volume.

```sh
skiff mcp [flags]
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--read-only` |  | leave out the tools that change things |

## skiff router

```sh

```

| Flag | Default | What it does |
| --- | --- | --- |

| `--metrics-file` |  | file to snapshot request metrics to (default ~/.skiff/metrics.json) |
| `--panel` | `127.0.0.1:7070` | fallback control panel address for dash.&lt;domain&gt; |

| `--requests-dir` |  | directory for the per-request log (default ~/.skiff/requests) |
| `--site-app` | `www` | app that serves the apex + www.&lt;domain&gt; |
| `--smtp-addr` | `:25` | address to receive forwarded email on (empty disables) |

## skiff run

Run a command once in a fresh container from an app's latest build

Run a command once in a fresh container from an app's latest build, with its environment and limits, and print its output as it comes. Skiff exits with the command's exit code. Ctrl-C stops the run.    skiff run shop-api -- npm run migrate   skiff run shop-api --timeout 2h -- "python backfill.py && echo done"

```sh
skiff run <app> -- <command> [flags]
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--timeout` | `0s` | how long it may take, like 2h (default 30m, up to 168h) |

## skiff server

Manage deploy servers

### skiff server reset-2fa

Turn off two-factor sign-in for an account that lost its device and recovery codes

Turns off two-factor sign-in for one dashboard account, so it can sign in with its password and set two-factor up again. Run it on the server, where access to the machine is the proof of identity.

```sh
skiff server reset-2fa <email>
```

### skiff server restore

Restore Skiff's own state onto this server from a control-plane backup

Restores the projects, settings, domains, tokens and history a control-plane backup holds into ~/.skiff. Run it on the new server before starting the panel. The recovery key is in the old dashboard under Server → Control-plane backup.

```sh
skiff server restore <backup.skiffbak> [flags]
```

| Flag | Default | What it does |
| --- | --- | --- |
| `--key` |  | the recovery key (64 hex characters) |

### skiff server setup

Install Docker on a fresh server over SSH

```sh
skiff server setup <user@host>
```
