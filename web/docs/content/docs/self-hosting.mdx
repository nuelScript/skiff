title: Self-hosting
description: "One command turns a fresh Linux server into your own deploy platform — the web dashboard, an edge router with automatic HTTPS, and everything needed to push apps to it."
---

## What you'll need

- A fresh **Ubuntu or Debian** server with a public IP and root SSH access (a $5/mo VPS is plenty to start). Running it on a Mac instead? See [On a Mac](#on-a-mac).
- A **domain** you can add DNS records to. Apps are served at `<app>.yourdomain.com` and the dashboard at `dash.yourdomain.com`.

## Install

SSH into your server and run this as root — replace `example.com` with your domain:

```sh title="on your server"
curl -fsSL https://useskiff.xyz/install | sh -s -- --domain example.com
```

The installer:

- installs Docker (if it isn't already),
- downloads the latest `skiff` binary,
- sets up systemd services for the **edge router** (binds :80 / :443 with Let's Encrypt) and the **control panel** (zero-downtime, blue-green),
- generates a one-time setup key and prints your dashboard URL.

<Callout>

It finishes by printing your DNS records, dashboard URL, and setup key. Keep that key — you need it for the first login.

</Callout>

## Point your DNS

Add these records at your DNS provider, pointing at your server's IP (the installer prints it). The wildcard covers every app and the dashboard in one record:

```text title="dns"
A    *.example.com    <your-server-ip>
A    example.com      <your-server-ip>    (optional — apex / marketing site)
```

Certificates are issued automatically on the first HTTPS request, so there's nothing to configure — just wait for DNS to propagate (usually a few minutes).

## First login

<Steps>
<Step>
### Open your dashboard

Visit `https://dash.example.com` once DNS resolves. The first visit asks you to create the owner account.
</Step>
<Step>
### Enter the setup key

Paste the setup key the installer printed, then set your email and password. That's the owner account — teammates join later by invite.
</Step>
<Step>
### Deploy your first app

Click **Deploy**, paste a Git repository URL (or connect GitHub), pick a name and port, and Skiff builds and runs it at `<name>.example.com` with its own certificate.
</Step>
</Steps>

## Connect GitHub (optional)

For push-to-deploy — a `git push` rebuilds and ships automatically, and branches can spin up preview environments — install the Skiff GitHub App from **Settings → Integrations** in the dashboard and pick which repos it can access. Without it, you can still deploy any public repo (or a private one with a token) by pasting its URL.

## Send email (optional)

Skiff can email team invites and alerts. Add an SMTP relay to `/etc/skiff/skiff.env`:

```text title="/etc/skiff/skiff.env"
SKIFF_SMTP_HOST=smtp.provider.com
SKIFF_SMTP_PORT=587
SKIFF_SMTP_USER=...
SKIFF_SMTP_PASS=...
SKIFF_SMTP_FROM=skiff@example.com
```

Then restart Skiff with `systemctl restart skiff-router skiff-panel@7070`. Emails arrive from **Skiff** at the `SKIFF_SMTP_FROM` address. Without a relay, an invite gives you a link to share yourself, and alerts can still go to Slack or a webhook.

## Updating

Re-run the installer any time to update to the latest release. Your data, apps, and setup key are preserved — it swaps the binary and restarts the services:

```sh title="on your server"
curl -fsSL https://useskiff.xyz/install | sh -s -- --domain example.com
```

## Troubleshooting

Check the services and their logs over SSH:

```sh title="on your server"
systemctl status skiff-router skiff-panel@7070
journalctl -u skiff-router -n 50 --no-pager
journalctl -u skiff-panel@7070 -n 50 --no-pager
```

- **Dashboard won't load / no certificate:** confirm `dash.example.com` resolves to your server's IP. Certs issue on the first request once DNS is correct.
- **An app 404s:** check it's running under **Server** in the dashboard, and that `<app>.example.com` is covered by your wildcard record.
- **Ports 80/443 in use:** make sure nothing else (nginx, Apache, Caddy) is bound to them — the Skiff router needs both.
- **Locked out by two-factor:** if you've lost both your authenticator and your recovery codes, turn two-factor off for your account from the server, then sign in with your password and set it up again:

  ```sh title="on your server"
  skiff server reset-2fa you@example.com
  ```

## On a Mac

The same platform runs on a Mac, such as a Mac mini under a desk. The installer sets up the same router and control panel, but as launchd agents in your login session instead of systemd services, and keeps everything under `~/.skiff`.

You'll need:

- **Docker Desktop**, installed and running. The installer doesn't install it, and stops if `docker` doesn't answer.
- The **Xcode command line tools** (`xcode-select --install`), which include git.
- A **domain**, and ports **80** and **443** forwarded from your router to the Mac, so the internet can reach it.

Run the installer as your own user, not root and without `sudo`:

```sh title="on the Mac"
curl -fsSL https://useskiff.xyz/install | sh -s -- --domain example.com
```

It checks Docker, downloads the macOS binary (verified against the release checksums) into `~/.skiff/bin`, starts the two agents (`xyz.useskiff.router` and `xyz.useskiff.panel.7070`), and prints your DNS records and setup key. From there, [point your DNS](#point-your-dns) and sign in as above.

<Callout>

**Keep the Mac awake and logged in.** The agents and Docker Desktop run in your login session, so a Mac that is asleep, or sitting at the login screen after a restart, serves nothing. In System Settings, stop the Mac sleeping automatically, turn on **Start Docker Desktop when you sign in**, and turn on automatic login (macOS doesn't offer it with FileVault on).

</Callout>

What differs from a Linux server:

| | Linux | Mac |
| --- | --- | --- |
| Settings (SMTP and so on) | `/etc/skiff/skiff.env` | `~/.skiff/skiff.env` |
| Restart | `systemctl restart skiff-router skiff-panel@7070` | `launchctl kickstart -k gui/$(id -u)/xyz.useskiff.router` and `…/xyz.useskiff.panel.7070` |
| Logs | `journalctl -u skiff-router` | `~/.skiff/logs/router.log` and `panel.log` |
| Update | re-run the installer | re-run the installer |

On a Mac, `~/.skiff/skiff.env` is read by the shell, not as plain `KEY=value` lines. Wrap any value with spaces, or characters such as `$`, `;`, `<` or quotes, in single quotes, for example `SKIFF_SMTP_PASS='p@ss word'`. To put a single quote inside a value, write it as `'\''`. Otherwise the shell reads the value differently, or drops it.

Not supported on a Mac yet: the panel updating itself from its own repository, `skiff db connect`, deploying to the Mac from another machine over SSH (`[server] host`), and the CPU, memory and uptime on the **Server** page.

To remove Skiff, run the installer with `--uninstall`. It stops the agents and deletes the binary. Your apps keep running in Docker, and your data stays in `~/.skiff` until you delete it:

```sh title="on the Mac"
curl -fsSL https://useskiff.xyz/install | sh -s -- --uninstall
```

Check the agents and their logs:

```sh title="on the Mac"
launchctl print gui/$(id -u)/xyz.useskiff.router | grep -E 'state|last exit'
tail -n 50 ~/.skiff/logs/router.log
tail -n 50 ~/.skiff/logs/panel.log
```

If the macOS firewall is on and asks whether `skiff` may accept incoming connections, allow it, or it can't serve ports 80 and 443.
